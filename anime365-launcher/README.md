# Локальный Anime365: модуль запуска TizenBrew

Модуль открывает `file:///home/owner/share/anime365.html` внутри готового TizenBrew. Его можно выбрать штатным автозапуском TizenBrew.

Здесь только описание запуска, пустой скрипт совместимого формата и служебное копирование уже имеющейся локальной страницы из SDK staging в постоянную папку на самом ТВ. Приложение, аккаунт и история просмотра отсутствуют в этом пакете: они остаются на домашнем телевизоре. Файлы не содержат видео, ссылок на видео, ключей, адресов домашней сети или личных настроек.

Сам по себе модуль не получает Anime365 из интернета и не подключает к аккаунту: необходима заранее подготовленная локальная страница на телевизоре. Перед включением автозапуска нужно один раз запустить служебное копирование и проверить страницу в постоянной папке. После этого исходный SDK staging для просмотра не нужен; существующая постоянная страница не перезаписывается. Компьютер для просмотра не нужен. Для штатной работы TizenBrew требуется Developer Mode с Host PC IP `127.0.0.1` и перезапуск телевизора, согласно руководству TizenBrew.

Лампа не используется и не изменяется. Собственный WGT и сертификаты для этого модуля не создаются. Интернет нужен TizenBrew для загрузки описания/скрипта модуля и Anime365 для каталога/видео.

Версия 0.2.0 добавляет службу обслуживания на порту 8096 в локальной сети. Все запросы требуют отдельный случайный ключ с телевизора; он отсутствует в пакете. Поддерживаются состояние, фиксированные кнопки пульта, открытие TizenBrew, перезагрузка страницы, атомарное обновление только Anime365 с проверкой SHA256 и откатом. Общего доступа к файлам и командной оболочки нет. Ключ аккаунта и история службе не нужны. Для управления интерфейсом локальная страница должна содержать невидимый bridge. Службу нужно добавить в штатный список автозапуска служб TizenBrew. Обновление ссылки модуля ограничено этим же репозиторием/каталогом и сохраняет другие модули и настройки.
Версия 0.2.1 загружает локальный HTML через штатный инжектор модулей внутри нативной страницы TizenBrew; прямой переход из меню к внешнему файловому пути больше не требуется. Медийные клавиши регистрируются только при наличии в getSupportedKeys. HTML и данные аккаунта в публичном модуле по-прежнему отсутствуют.
